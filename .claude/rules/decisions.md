# Helper

## Windows
- 보안 프로그램 등 환경별 특성을 근거로 한 설계·설명 금지
  - 사유: 특정 PC 환경이 아닌 일반 사용 기준으로 설계
  - 대기·재시도는 일반 규칙으로 설명
- wintun.dll: Helper 시작 때 한 번 로드, 해제 없음
  - 사유: openconnect가 세션이 끝날 때마다 DLL을 해제하는데, 이때 Wintun의 남은 어댑터 정리가 같은 DLL 코드를 실행 중일 수 있음
  - 해제되면 Helper 비정상 종료 위험
  - openconnect 수정 없이 참조 횟수만으로 해제 방지
- 의도된 Helper 재시작: 종료 코드 4로 프로세스 종료, 서비스 중지 미보고
  - 대상: 세션 정리 멈춤, 내부 멈춤, 패닉
  - 사유: abort()의 종료 상태(0xC0000409)는 스택 버퍼 오버런으로 기록되어, 의도된 재시작이 메모리 손상 크래시로 보임
  - 재실행: 서비스 관리자의 실패 시 재시작 설정
  - 4를 고른 이유: 1·2는 Helper가 이미 사용, 3은 C 런타임 abort()의 종료 코드
  - macOS: abort() 유지, launchd가 재시작
- 연결당 한 번에 하나만 처리하는 요청
  - 예외 route 읽기·쓰기
  - 업데이트 준비·설치
  - 사유: 다른 로컬 프로그램의 요청 누적 방지

## macOS
- 앱↔Helper 통신: NSXPC 유지
  - 사유: 설치 중 다른 빌드 Helper와 getVersion·exitWhenIdle로 통신
  - getVersion·exitWhenIdle의 selector·응답 형식 변경 금지
- XPC 프로토콜 선언: 앱·Helper 공용 ObjC 헤더 하나
  - 사유: 두 선언의 수동 일치 제거
- SIGTERM 수신: signal-hook 사용
  - 사유: 신호 차단 방식은 Helper가 실행하는 자식 프로세스에 차단 상태 상속

## Windows
- 설치 패키지의 Helper 서비스 시작 없음
  - 사유: 서비스 시작의 기한 초과 시 설치 실패 처리
- Helper 서비스 시작: 앱 시작 때 앱 담당
- OpenConnect 빌드 환경: C:\msys64의 MSYS2 UCRT64 고정
  - 사유: PATH의 bash는 Git Bash·WSL일 수 있음
  - C:\msys64: MSYS2 설치 프로그램 기본 폴더, GitHub Windows runner 설치 위치

  - 사유: 시스템 계정 설치 프로그램의 사용자 권한 앱 실행 불가

  - 작업 스케줄러: 실패 시 예약 작업 잔존
  - 작업 스케줄러: 기본 우선순위·실행 시간 제한 적용
  - 사용자 권한 설치 후 관리자 권한 전환: 업데이트마다 확인 창
  - 사용자 권한 설치 후 관리자 권한 전환: 일반 사용자 업데이트 불가
- 대기 프로세스 시작: 설치 요청 전
  - 사유: 대기 프로세스 시작 실패 시 설치 미시작
- 설치 프로그램 번호 전달: 대기 프로세스 시작 뒤 입력으로 전달
- 대기 대상 판정: 프로세스 번호와 프로그램 이름
