---
name: root-cause
description: 장애·버그 원인 확정과 대응
---

# 1. 복구
- 사용자 영향(VPN 끊김 등) 복구 우선
- 복구 수단: 직전 정상 빌드·설정

# 2. 사실 수집
- 사용자 관찰 증상 확인: 본 현상, 시각, 직전 조작
- 로그·시스템 상태·OS 로그는 직접 수집
- 수집 대상의 빌드·OS·시각 기록

# 3. 원인 확정
- 사실의 시간순 정리
- 가설은 소스·실측으로 확인 전 "가설" 표기
- 같은 증상 재현 불가 가설은 원인 확정 금지
- 다른 빌드·환경 결과로 판정 금지
- 대리 지표(로그 문구, 가짜 시험, 리뷰 통과) 근거 금지

# 4. 원칙 대조
- 위반한 시스템 원칙 특정
- 같은 원칙 위반 위치 전수 탐색

# 5. 대응안
- 원인 제거만, 증상 은폐 금지
- 원칙 기준 방안과 영향 범위

# 6. 검증
- 수정 전 재현 조건 확정
- 수정 후 같은 조건에서 직접 관찰

# 7. 보고
- 결론 우선: 무엇이 왜 일어났는지 한 줄
- 설명 기준: 동작·사용자 영향, 코드 용어 최소화
- 근거: 확인 수준(실측·소스·가설) 표기, 코드 위치는 참고만
- 대응: 변경 후 사용자에게 보이는 효과
- 검증 결과: 같은 조건의 수정 전·후 관찰 대조
