FortiVPNManager 구조 설계

재구현 대상의 기능 구성, 아키텍처 구성, 디렉토리 구성 기준입니다. 영역·묶음·헤더의 구분과 역할, 디렉토리와 crate 구성을 다루고, 공개 인터페이스와 세부 동작은 다루지 않습니다.

2. 구성 단계

단계단위대표 파일내용
영역디렉토리없음시스템, 사용자, 공용
묶음cratelib.rs연결 관리, 프로토콜 관리, 서비스 관리
헤더모듈mod.rs헤더의 총괄 구현체
세부 기능모듈 파일없음총괄 구현체가 쓰는 기능
묶음다루는 대상
연결 관리VPN 연결
프로토콜 관리앱과 Helper 사이 통신의 구현체
서비스 관리서비스로 실행되는 프로그램 자신

총괄 구현체

  • 대상마다 그 이름을 가진 구현체가 최소 하나 있습니다.
  • 서비스 관리, 헤더, 로그 관리, UI의 세 기능에 적용합니다.
  • 서비스 관리의 총괄 구현체가 메인 서비스입니다.
  • 세부 기능은 헤더 디렉토리 안에 모듈 파일로 추가합니다.

단계의 예외

  • 메인 서비스는 헤더 없이 서비스 관리 crate의 lib.rs에 있습니다.
  • 로그 관리는 묶음 밖의 crate입니다.
  • UI는 묶음 밖이고 Rust crate가 아닙니다.

3. 실행 흐름

Helper

  1. main 진입system/helper
  2. 메인 서비스 생성system/service
  3. 메인 루프
  4. 메인 루프 종료
  5. main 종료

앱

  1. main 진입user/app · Swift, C#
  2. 시작 호출user/app · Rust 통로
  3. 메인 서비스 생성user/service
  4. 메인 루프
  5. UI 실행user/ui
  6. 메인 루프 종료 통지
  7. main 종료
  • 진입점은 메인 서비스 생성과 종료만 맡습니다.
  • 메인 서비스는 기능을 만들어 조합하고, 메인 루프를 관리하며, 서비스 시작과 종료의 경계가 됩니다.
  • 앱 진입점의 Rust 통로는 메인 서비스 시작·종료 호출과, UI와 메인 서비스 사이의 통로를 맡습니다.

  • app은 Rust 통로, Swift main, C# main으로 이루어집니다.
  • 진입 코드만 두고, 화면 구성은 두지 않습니다.

UI와 리소스

  • UI는 표시와 입력만 맡습니다.
  • UI가 아닌 헤더는 UI를 참조하지 않습니다.
  • UI는 OS 이름으로 먼저 나누고, 세 기능 디렉토리를 두 OS에 똑같이 둡니다.
  • 문장 생성 코드는 ui/OS/Localization에, 앱 리소스는 resources/OS/유형에 둡니다.
  • 번역 리소스를 쓰는 곳은 UI뿐입니다.

10. 구현 단계 결정 항목

  • 헤더 안 세부 모듈의 수와 이름
  • 총괄 구현체의 영문 이름과 공개 인터페이스
  • OS API의 OS별 모듈을 쓰는 쪽에 내주는 방식
  • 진입점도 UI도 아닌 Swift·C# 코드의 필요 여부
  • 최상위 C# 프로젝트의 소스 경로 지정과 중간 산출물 분리
